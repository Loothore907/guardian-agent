This file is the authority for public security language. A design description does not become a guarantee merely because it appears in documentation or code.

## Status definitions

- **Goal** - intended behavior without completed implementation evidence.
- **Implemented** - present in code but not yet backed by the complete required evidence.
- **Implemented locally** - the same evidence level as Implemented, explicitly
  limited to local composition; it is not a separate assurance upgrade.
- **Implemented and tested** - supported by reproducible tests identified here.
- **Not claimed** - deliberately excluded or unsupported.

## Development context reader (issue #51)

regular-file HEAD blob reads, exclusion of staged/unstaged/untracked content,

## Local denial/recovery slice (2026-09-09)

[The deterministic denial/recovery evidence](development/evidence/2026-09-09-local-denial-recovery.md)
uses the production reference-supervisor composition with supervised synthetic
service children. One approved release fixture is retrieved, the same worker emits
an outside-domain request, research policy denies it before its provider transport,
and the worker receives an allowlisted cause/stage with unchanged consumable
counters and non-increasing remaining duration before
returning the required dated, prerequisite-qualified and cited answer. Authority
persistence records contiguous proposal/decision/dispatch/feedback/completion/
terminal evidence and ends the durable session as `completed`.

This is Implemented and tested offline for the exact deterministic composition.
It adds no live-model causation, paid-provider, hosted-containment or Enforced
evidence. The September 8 actual-model run remains Observed resistance rather than
a denial because it emitted no forbidden request.

## KC hosted gate (2026-09-07)

[The bounded hosted gate](development/evidence/2026-09-07-kc-hosted-gate.md)
adds intended-host disabled startup, process/filesystem/network probes, exact IAM
and protected SecretStash reads, authenticated model-price inventory, service-clock
policy update, DNS-only TLS, negative-route authentication and a durable
fail-closed settlement. The first exact draft was admitted but failed before any
provider call because the required credential-free `git archive` was not an exact
Git working tree. The ledger forfeited USD 0.10 with `usage: []`; no confirmation
or retry was sent. Public TLS also became unreliable after the negative-test burst.
Issue #40 now has an offline implementation: protected research-only startup
requires a canonical archive entry manifest, workspace planning treats only its
paths as authorized, and a production-supervisor child test prepares a real
gitless archive root. ADR-0056 records the allowed and near-miss evidence. This
removes the reproduced source-contract defect locally; it does not retroactively
change the failed hosted result or promote hosted availability, live provider
behavior, the successful-journey gate or any Enforced claim.

After explicit transfer approval, the stopped-host operator helper copied the
existing Nebius/Tavily testing keys into two exact KC resources and verified each
primary payload against its retained Windows original without printing values.
Exact-resource runtime payload-reader grants and sole runtime-group membership
were checked. This proves the operator copy, not actual runtime retrieval or
live provider behavior; see the continuation's post-shutdown enrollment evidence.

[KC native Linux checkpoint](development/evidence/2026-09-05-kc-linux-acceptance.md)
adds reproducible current-source platform and C4 reference-runtime evidence on
the KC VM. The final suite passed, but earlier intermittent authority-child

SecretStash resource was retrieved through a resource-scoped payload-reader role;

fixture through the CLI. The checkpoint records the probe, source identity and
677-pass/6-skip full suite. Real credentials and live provider behavior remain
unverified; this narrow synthetic evidence does not establish full
hosted containment, availability or an assurance upgrade.

[C7 evidence](development/evidence/2026-09-05-c7-runtime.md) maps typed sanitized
research/GitHub results, exact result/turn/grant binding, durable replay/accounting,
bounded continuation and portal confirmation to reproducible local tests.
Service-child scenarios use synthetic worker requests and provider transports;
they establish content delivery and runtime decisions, not real-model attack rates.
The trusted host factory composes the existing budget and fixture interfaces.
Actual hosted budget/service readiness, protected provider containment and live
model behavior remain **not claimed**. No Enforced assurance promotion or live
scenario registration follows from these local checks.

## Prior launch and headless slice (2026-09-05)

The newer [judge portal evidence](development/evidence/2026-09-05-judge-portal.md)
establishes local schema rejection, authenticated one-use caller/preview binding,
synthetic budget ordering/settlement and persistent fixture exclusivity. The evidence
schema distinguishes model claims from boundary observations but does not attest to
their provenance by itself. The newer C7 tests cover local adapter/grant composition.
Live portal provider behavior, per-person identity, hosted isolation and successful
seeded attacks remain **not claimed**. Default portal execution is disabled.

**Implemented and tested locally:** exact action intent participates in the initial
launch preview; a bound grant is stored before worker execution. The competition
command uses that grant without another prompt. Trusted standing deployment
consent preserves its original timestamp and cannot be selected by public HTTP
inputs. The headless executor checks fixed scope, expiry, budget bindings, replay,
cancellation and concurrency. Broker-only GitHub installation-token minting uses
read-only synthetic SecretStash access and fails closed on renewal failure.

[Evidence and exact limits](development/evidence/2026-09-05-launch-headless.md)
include the real Windows/WSL and native Linux namespace probes. **Not claimed:**
hosted availability, live VM IAM/SecretStash isolation, real token renewal, two-hour
worker longevity, unattended host restart recovery, WSL repair, production identity
verification or a generalized workflow. Standing deployment config is trusted host
input, not a cryptographically signed public consent mechanism.

## Typed session-plan slice (2026-09-05)

**Implemented and tested locally:** one trusted development confirmation supports
subsequent exact GitHub read/squash operations within the grant's limits, without
an additional exact approval. The broker preserves risk escalation, checks current
authority after credential resolution, and atomically consumes attempts. Durable
proposals do not create authority. Reproducible tests and current gate results are
in [the evidence record](development/evidence/2026-09-05-session-authority.md).
This claim excludes generalized workflows, a production confirmation ceremony,
live headless secret retrieval/renewal, automatic recovery, and atomic remote base-branch
protection. It does not promote session assurance to Enforced.

binding before Guardian inference, session-only cost receipts and bounded multi-turn

establishes complete provider containment or hosted assurance.

Any pull request that changes this matrix must identify:

1. the implementation revision;
2. exact reproducible test commands;
3. relevant fixtures and expected failures;
4. supported runtime and configuration;
5. residual limitations; and
6. wording changes required in README, submission text, demo UI, and video materials.
