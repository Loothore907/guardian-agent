# ADR-0040: Local-only Linux Secret Service routing

- Status: Accepted
- Date: 2026-09-04
- Extends: ADR-0010 and ADR-0038

## Context

The W26 disposable Secret Service lifecycle proved that the fixed Linux adapter
can use a real D-Bus Secret Service. It did not constrain the inherited D-Bus
address beyond length and control-character checks. D-Bus addresses can name
remote transports or multiple fallback transports. Forwarding either shape from
a contaminated host environment could route a credential operation outside the
intended local user session.

The supported Ubuntu 22.04 environments use one of two local forms: the standard
current-user bus at `/run/user/<uid>/bus`, or the Unix abstract socket created by
`dbus-run-session`. Both authenticate local peers; neither requires an ambient
network transport. The current-user runtime directory is `/run/user/<uid>`.

## Decision

Before starting a credential-holding service or `/usr/bin/secret-tool`, Guardian
requires both `DBUS_SESSION_BUS_ADDRESS` and `XDG_RUNTIME_DIR`. The runtime
directory must normalize to `/run/user/<current uid>`. The bus address must name
exactly one supported local Unix transport:

- `unix:path=/run/user/<uid>/bus`; or
- the bounded `unix:abstract=/tmp/dbus-...` form generated by
  `dbus-run-session`.

Either form may include one lowercase 32-hex-digit D-Bus GUID. Remote transports,
multiple fallback addresses, other filesystem paths, mismatched user runtime
directories, missing values, control characters, and oversized values fail
closed before a credential helper or provider service starts. Credential-holding
children still inherit only their fixed provider selector plus these two routing
values. The untrusted command sandbox receives neither value and cannot see the
host `/run` or `/tmp` namespaces.

## Consequences

- A contaminated environment cannot redirect Secret Service lookup over TCP or
  to an arbitrary filesystem socket.
- Linux credential use now fails earlier and with the existing sanitized error
  when a supported local user session is absent.
- Custom D-Bus layouts are unsupported until their ownership, peer
  authentication, and containment properties are separately designed and
  tested.
- This narrows routing but does not by itself prove a protected provider call,
  persistent desktop-keyring configuration, or every trusted-service peer.
