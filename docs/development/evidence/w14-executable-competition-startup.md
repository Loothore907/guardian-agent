## Implemented path

```text
exact `guardian competition` command
  -> strict named public deployment inputs
  -> fresh session, caller, principal, and connection identifiers
  -> trusted competition mission ceiling and narrower worker tool catalog
  -> exact session preview confirmation
  -> active Enforced reference-session result
  -> canonical unsafe and legitimate requests derived from that activation
  -> exact W13 merge confirmation
  -> fixed journey runner
  -> minimized result and guaranteed supervisor close
```

The executable accepts no arbitrary URL, header, command, environment, model ID,
provider transport, credential, credential-store handle, session binding, or
approval object. Named deployment inputs contain only the public GitHub client ID,
two exact public pull-request versions, a bounded research query, allowlisted
domains, and required terms. Secret-like research text is rejected before startup.

The supervisor derives the credential-store handle from its fresh connection ID,
owns the research IPC credentials, and creates and attaches the narrow durable
GitHub connection only inside exact-confirmed session launch. Declining the
preview therefore leaves no active connection authority behind. The exact
request/session/caller/connection/mission/profile/policy bindings are constructed
only after a schema-validated active Enforced bootstrap result.

ADR-0030 separates the human-confirmed mission/session ceiling from the native
worker's model-visible tool catalog. The competition mission permits bounded
Guardian research and an exact-approved merge, but the current worker sees only
`guardian.session_status` and `guardian.local_command`. Both sets are displayed
and bound into the preview; the worker set must be a unique subset.

## Residual limitations

- The application-level completed-path test injects a deterministic supervisor.
  W9-W11 separately retain actual child-process and fixed-composition evidence;
  one ordinary test does not replace the credential-backed protected journey.
- The executable currently selects fake mission-dialogue, setup-risk, and worker
  roles. Live roles will be introduced one at a time under ADR-0029 rather than by
  accepting caller-supplied model IDs.
- The production research and broker children remain credential-store-backed and
  were not started in this slice. No Tavily, Nebius, or GitHub provider call ran.
- The exact expected pull-request heads are trusted public deployment inputs and
  must be refreshed and independently revalidated before a protected run.
- Protected live pre-activation, native-worker, Tavily, Nemotron-through-broker,
  denial, merge, mutation/replay, and redaction evidence remain. WebAuthn and
  platform peer-identity parity remain later gates.
